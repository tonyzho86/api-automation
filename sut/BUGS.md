# 靶场缺陷清单(答案)

> ⚠️ **建议先自己测,再翻这一页。**
> 自己用接口测试找出来,和直接看答案,学到的东西差好几倍。

一共 **6 个缺陷**,覆盖接口测试里最典型的两大类:

- **参数与边界类**(BUG-1、BUG-4)
- **安全与鉴权类**(BUG-2、BUG-3)
- **业务逻辑类**(BUG-5、BUG-6)

## BUG-1 · 分页参数边界导致服务端 500

- **接口**:`GET /api/products?size=0`
- **现象**:返回 `500 Internal Server Error`(除零),而不是 `400 Bad Request`。
- **根因**:`total_pages = (total + size - 1) // size` 没校验 `size > 0`。
- **怎么测出来**:分页参数要测边界 —— `size=0`、`size=-1`、`page=0`、`page=99999`。
- **期望行为**:非法参数 → `400`;或 `size=0` 按默认值处理。

## BUG-2 · 订单详情越权访问

- **接口**:`GET /api/orders/{id}`
- **现象**:**不带 token** 也能拿到订单内容;换一个账号也能看到别人的订单。
- **根因**:这个接口完全没加鉴权、也没校验订单归属。
- **怎么测出来**:安全用例 —— 同一资源换身份访问。用 alice 下单,然后用 admin 的 token(或干脆不带 token)去读。
- **期望行为**:未登录 → `401`;登录了但不是自己的单 → `403`。
- **彩蛋**:旁边的 `DELETE /api/orders/{id}` 是**对的**(校验了归属)。同一个资源、两套标准 —— 这正是接口测试最容易漏的地方。

## BUG-3 · 登录失败返回 200

- **接口**:`POST /api/login`(密码故意填错)
- **现象**:HTTP 状态码是 `200`,响应体是 `{"token": null, "user": null}`。
- **根因**:失败分支没有返回 `401`。
- **怎么测出来**:正向——密码错误要断言状态码;别只看"没报错"。
- **期望行为**:凭据错误 → `401`。

## BUG-4 · 购物车数量可为 0 或负数

- **接口**:`POST /api/cart/items`,body `{"product_id": 1, "quantity": -5}`
- **现象**:`200`,商品被以负数"加"进购物车,金额变小甚至变负。
- **根因**:没有校验 `quantity` 必须是正整数。
- **怎么测出来**:数值参数的边界和非法值 —— `0`、`-1`、超大值、非数字。
- **期望行为**:非法数量 → `400`。

## BUG-5 · 优惠券重复减免(金额算错)

- **接口**:`POST /api/orders`,用 `SAVE20`(满 100 减 20),且订单里有 **2 种以上商品**。
- **现象**:`discount` 减了 40(甚至更多),正确应该只减 20。应付金额算少了。
- **根因**:`sut/store.py → order_amount()` 里,优惠券按"商品行数"循环减,而不是订单级减一次。
- **怎么测出来**:金额类断言要构造**多行商品**的数据;一行商品时这个 bug 不会暴露。
- **期望行为**:满 100 减 20,整单只减一次。

## BUG-6 · 幂等键被忽略(重复下单)

- **接口**:`POST /api/orders`,带相同 `Idempotency-Key` 请求头连发两次。
- **现象**:两笔订单都被创建了(`201` × 2),返回两个不同的订单号。
- **根因**:接口收下了 `Idempotency-Key` 却没用它去重。
- **怎么测出来**:幂等性用例 —— 同一请求重放,断言"只产生一个副作用"。
- **期望行为**:同一幂等键重复提交 → 返回**同一个**订单(或 `409`),只创建一笔。
